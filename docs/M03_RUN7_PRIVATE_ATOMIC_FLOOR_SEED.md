## Contract and atomicity boundary

It calculates `max(original historical sequence, separately frozen original DocumentProperties counter)` for each of the 38 Config-pinned families without logging those values.

The private **synthetic** table `synthetic_m03_id_counters` is seeded by exactly one parameterized SQLite `WITH floors(...) INSERT INTO ... SELECT ...` statement with **41 total bindings**: 38 private source-derived floor numbers and 3 trusted tenant scopes. All 38 family keys/prefixes are fixed compile-time Config-pinned SQL literals, **never caller-provided values**. This respects Cloudflare D1's 100-parameter limit. The statement commits **all 38 rows or zero rows**. It refuses to insert anything for the given tenant if **any existing counter or issued receipt** exists; a complete exact prior seed is treated as a stable replay and is verified (not rewritten). An existing partial, wrong, extra, missing, bad-prefix, wrong-floor or prior-receipt state is rejected by the Run 6 audit. A trigger/SQL error aborts the entire single statement, with no partial seeded family rows. Other tenants are unchanged.

Only after D1 confirms statement success does Run 6's existing read-only audit re-read all 38 counters, enforce the frozen floors and zero receipts, and return a fixed nonauthorizing result. An ambiguous/failed SQL result is **not** treated as success; retrying with the same evidence is safe if the previous statement committed. **This post-commit readback is not a transaction with the prior source read, and it does not prevent a later staff/migration write or establish lasting authority.** Trusted caller is offline; there is no public route or secret path.
