## Security and bug-bash findings

**QA-HOLD-01 — Critical integration blocker, not a new code regression.** `src/rpc/registry.js` intentionally registers zero endpoints; `src/index.js` health reports `database: not-connected`. Users cannot execute authenticated live POS transactions. This is an explicit safe-fail stance until M02/M03/M04/M05 integration evidence is approved. **Owner:** M03 integrator with M04, M05, M06. **Track:** #314, #456. Do **not** enable a public writer just to make browser tests pass.

**QA-HOLD-02 — Critical scope gap.** The real source-shaped full `completeSale` path has no verified production schema/write integration for immutable multi-unit/Tiles stock, split payments, Customer due, vendor sourcing, Cash Session, replay, failed-batch rollback, draft consumption and invoice IDs. The synthetic D1 proof uses a simple single SKU and cannot satisfy this AC. **Owner:** M06 + M03/M05/M08 signed contract. **Track:** #314.

**QA-HOLD-03 — Critical acceptance-gap.** No end-to-end authenticated POS checkout, posted receipt, mobile/tablet flow or actual sale screenshot/HAR/console/network trace was produced by this audit; the existing M01 screenshots exercise UI visibility under mocked auth, not sale posting. **Owner:** M01 for browser tests, M06 for sale AC, M09 for print. Defer positive live checkout until public write gate; continue fail-closed negative checks now.

**QA-HOLD-04 — Security-review evidence missing.** The external Super QA process requires `pr-security-review`; no execution report for it was available in this audit. A manual source inspection of no-public-RPC cannot substitute for that run. **Owner:** M04/M06/M11 integrator. Avoid asserting a clean security review.

No confirmed new independent M06 product-code defect was established by this static audit. The holds are **known, release-blocking integration/test gaps**, not evidence that existing pure-helper tests are false.
