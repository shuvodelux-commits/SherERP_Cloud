Reviewed actual frozen functions in `legacy/source/Purchase.gs`, `Suppliers.gs`, `SupplierSettlement.gs`, `PurchaseReturn.gs`, `SalesReturn.gs`, `CashSession.gs`, `Utils.gs`; the existing source oracle `tests/contract/m08-purchase-source-financial.test.mjs` and precision suite `tests/contract/m03-run3-purchase-precision-source.test.mjs`. Reuse [merged M02/M08 source contract](2026-11-20-m02-m08-purchase-financial-contract.md), [supplier review](2026-11-20-m03-run3-supplier-signoff.md), [independent accounting QA](2026-11-20-independent-accounting-qa.md), ADR-007 and [posting gate](2026-11-20-m03-purchase-posting-gate.md).

- `Purchase.gs:109-122,131-168`: permission `purchase:add`, active Cash Session at entry, active original Supplier ID, exact `subtotal += qty * price`; nonnegative discount is retained; grand total floors at zero; immediate paid amount caps at grand total; zero paid leaves blank method.
- `Purchase.gs:174-236`: original Purchase/Line/Movement/Lot IDs, source purchase date on lot (not created-at), bank/cash debit only for paid portion, Supplier Ledger **Debit** only for unpaid portion. The bank-path comment at lines 208–210 describes no session requirement, **but the unconditional gate at line 110 is executable behavior**. Treat this as a source comment inconsistency, not permission to skip the gate.
- `Suppliers.gs:220-301`: supplier payment requires session, increases Supplier Ledger **Credit** by payment + permitted settlement discount, debits cash/bank only by the money amount; zero-discount overpayment can create negative signed due (advance). Source opening balance is historical, not drawer turnover.
- `SupplierSettlement.gs:16-18,120-169,181-268`: provenance replay ordered by Date, physical row index and Ledger ID; untargeted money pays oldest obligation; targeted return credit settles original purchase first, retains leftover noncash store credit; cash-backed supplier advances are separate pools. Unknown historical row signs are preserved without invented purchase allocation.
- `PurchaseReturn.gs:204-223,251-270,309-323`: effective post-discount return unit price, **round each return** to 0.01 BDT; Cash refund requires verified collectible money minus earlier refunds; Supplier Credit reduces native due without a money-book movement.
- `SalesReturn.gs:470-487,644-660`: selected Cash refund is an outgoing cash payment and leaves Customer due unchanged, including unpaid invoices; Store Credit reduces the selected Customer account instead. This is explicitly explained in the original `returns.html`; `salesReturnCashRefundAvailable_` is displayed for reference, not a cash-refund posting ceiling.
- `CashSession.gs:336-346`: a transaction requiring a cash session is blocked unless a session is exactly Open. A future per-tenant bypass setting is a **separate policy change**, not source behavior.
- `Utils.gs:160-179`: `roundMoney_` uses JS `Math.round((n + EPSILON) * 100) / 100`; proportional return value uses Grand Total / Subtotal. JS binary floating point is not exact-decimal operational storage.
- **Evidence limitation:** synthetic source oracle and local Workerd/D1 fixture results in merged #718 (26 source + 183 isolated D1 test passes) **do not certify the private historic ledger or a shared operational D1 purchase writer**. All 49 source groups were still un-reconciled in that audit. The clean empty-shop approval and historical-source cutover require distinct gates.
