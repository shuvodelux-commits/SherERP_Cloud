# Production MVP decision

**Hold production.** On target main `0deb878e003a6cc643e8a1231a1e7cc1c00c499d`, the public Worker has an empty RPC registry. The separate private Owner shell maps four calls. A shop cannot complete a sale by following the application screens. Adding D1 credentials to the public Worker would leave that problem in place and would violate preview isolation.

## Completion order

1. **M03/M04 security and installation.** Deliver a protected bootstrap and recovery path for one administrator. Add server-side Owner session expiry through the Shop SQL write boundary. Verify OTP replay, stale grants, disabled access and authenticated actor identity. Acceptance requires a fresh account with real Google and Access and two distinct users.
2. **M03 business lifecycle.** Connect the existing provisioning journal to a hosted provider, with a resumable operation ID and an explicit migration plan for each database. Check the immutable marker and receipts before enabling the Owner. Exercise two businesses, suspend/reactivate, owner replacement, support consent/revocation, and interruption after each irreversible step.
3. **M03 with the ERP module owners.** Connect the original private UI incrementally. Start with Party, product units, suppliers and opening inventory. Follow with purchase, FIFO sale, payment, return, correction and expense. Enforce permissions and idempotency inside each atomic SQL boundary. Reconcile gross Party accounts, stock, cash and bank after duplicate requests and failed writes. Verify reports, saved invoices and printouts from the same records.
4. **M10/M11 release rehearsal.** Use disposable hosted resources in a second account. Test GitHub merge deployment, Access, Google, persistence, cross-shop denial, migration replay, measured plan capacity, backup and restore, and Worker rollback with compatible data. Inspect Cloudflare build logs for the failed shell check. Record commits, versions, database identities, reconciliation totals and results before requesting cutover approval.

Defer billing, portfolio analytics and customizable permission editors. Additional dashboards and cosmetic changes do not advance the release checks above.

## Scope of this PR

Issue #699 covers portable installation. This change owns release scripts, their contract tests, a synthetic profile fixture, a package command and operator documentation. It changes no SQL, RPC, schema, original source or Worker entry point. Independent review identified two configuration mistakes that previously passed verification. A private Worker could take the public shell name and a verified D1 binding set could omit its sign-in rate limiter. Tests first failed with a missing exception or rejection. The fixed checks also reject zero and ambiguous leading-zero ingress namespace IDs. All 43 focused portability and deployment ownership checks passed locally.

Rehearse the private bundles with `npm run rehearse:private-bundles` in a disposable checkout. The fixture writes disabled profiles under the ignored Wrangler directory. Use a separate checkout for real account settings. The command packages both entry points and eleven Owner asset files with no credentials. Existing Workers Builds remains the deployment owner. Live Google, Cloudflare account provisioning, remote migrations, real business transactions and coordinated rollback were outside this local evidence. No merge or production change was performed.
