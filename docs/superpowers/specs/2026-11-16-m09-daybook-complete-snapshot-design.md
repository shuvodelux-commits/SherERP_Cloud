# M09 — compose complete authorized Day Book snapshots (read-only)

**Date:** 2026-11-16. **Source:** original `Mohim_ERP@29aa4a5c7a7062a49e6bf4758beda3a8d62d9ff2` `legacy/source/DayBook.gs::getDayBookTransactions`; owner-approved M00–M11 architecture; merged M09 per-section projection PRs #361, #369, #381, #386, #393; merged M09 Bank Book dedup, Cash Book running balance, filter/totals.

## Decision and scope
The frozen Day Book has one **ordered multi-source pipeline**, while the target repository now owns independently tested pure section projections. Compose the existing components instead of copying their financial rules into a new posting/SQL layer. New **internal, pure, read-only** `projectDayBookCompleteSnapshot(snapshot,filters={},isAdmin=false)` uses *only complete, pre-authorized, shop-local-normalized source arrays*; this is not a public Worker RPC or a D1 read adapter. Requires all 12 arrays: `sales`, `salesReturns`, `purchases`, `purchaseReturns`, `customerLedgerRows`, `supplierLedgerRows`, `expenses`, `financeTransactions`, `bankTransfers`, `bankEntries`, `stockMovements`, `cashBookRows`.

1. Validate the **entire** snapshot shape (own-data plain object, exact own keys), every array dense and own-data (no accessor/sparse slots/extra properties), every record plain own-data scalar and no nonfinite numeric values, **before** filtering or delegating; don't silently omit corrupt/deleted documents.
2. `filters.includeDeleted` is effective only when the caller supplies `isAdmin === true`. Caller must have already authenticated and authorized `daybook.view`, with one tenant/shop and all required source groups fully loaded; this function **cannot establish** auth or tenant isolation. `projectDayBookWindow` validates other filters; reject malformed filters through that component before sensitive rows are exposed. Require trusted boolean admin flag.
3. Delegate unmodified to six already-GREEN and source-oracle-backed components: Sales/Purchase; Sales/Purchase Return; Customer Payment/Customer Advance Refund/Supplier Payment; Expense/Finance; standalone Bank Book; Bank Transfer/Stock Adjustment. Preserve **original `DayBook.gs` source group order**: Sales → Sales Return → Purchase → Purchase Return → Customer Payment → Customer Advance Refund → Supplier Payment → Expense → Finance → Bank → Bank Transfer → Stock Adjustment. Do not invent money for bank transfers, stock adjustment or historical finance opening.
4. Source Bank Book deduplication must use **exact same visible source document groups as frozen `ownedReferences_`**: keep visible Sales, Purchases, Expenses, Customer Payment, Customer Advance Refund, Supplier Payment and Finance; always include Bank Transfers. Source-owned bank entries get suppressed to prevent double counting of bank-paid documents. Purchase Return credit classification uses complete Supplier Ledger, including source credit rows. Bank Book entries are complete source-normalized source records (including reversals).
5. Add running drawer balance from **authoritative active Cash Book rows**, never inferred Day Book cash amount. Use `projectDayBookRunningCash` **before** date/module/search filtering. Then `projectDayBookWindow` for original chronological descending rows, Administrator-only deleted visibility, query and per-addition rounded cash/bank totals. No asynchronous wall clock or new caches; no accounting/stock/Party updates.
6. No change to `src/rpc/registry.js`, `src/index.js`, M03/M04 auth, SQL schema, D1 production or previews, frozen GAS or original UI. All transactional module writers remain unchanged. No claim that partial D1 tables constitute a complete original business snapshot. No permissionless endpoint, no production deployment/active cash handling.

## Acceptance cases
- Complete empty snapshot → original empty response; incomplete input/accessor/sparse array/nonfinite value → throw with no partial results.
- Mixed source activity (Cash Sale + Sale Return, Bank Purchase, Purchase Return credit, Customer/Supplier settlement, advance refund, Expense, Finance opening, standalone Bank, Bank Transfer, Stock Adjustment) has one row per original source record; Bank Book duplicates suppressed; transfer and adjustment are net-zero.
- Cash Book-only chronology and tie behavior remain intact even when final filtered rows exclude cash predecessors; no fabricated running balance if cash book is empty.
- Document soft-deletion changes visible source groups by role; ignored for non-Administrator, displayed for Administrator includeDeleted with omitted deleted money in totals; never allow includeDeleted from non-admin to expose source.
- Data inputs not mutated or aliased; all bank-like methods preserved; filter totals equal displayed rows. Per-component tests retain their frozen source oracle.
- No public RPC route added, no D1 writes, no Cloudflare preview bindings; exact branch SHA checks before merge.
