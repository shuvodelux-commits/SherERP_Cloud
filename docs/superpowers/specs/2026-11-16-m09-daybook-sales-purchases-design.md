## Chosen independent scope

PR #350 merged Cash Book running balance; #342 Bank Book reference dedup; #329 final range/totals; #323 bootstrap. M03 has separately added an internal Day Book bootstrap bridge, not the full transaction feed. Full D1 transaction source tables, auth/tenant read, Cash Book reconciliation and reversal accounting remain gates owned by M02/M03/M05/M06/M07/M08. The next safely mergeable M09 step is a **pure source-shaped projection** of only Sales and Purchases. This does not invent missing D1 rows or turn on the public RPC.

`projectDayBookSalesPurchases(snapshot, isAdmin=false, includeDeleted=false)` returns original source-shaped Day Book rows in source section order (all Sales first, then Purchases), WITHOUT running cash balance. The snapshot must be complete, trusted own-data `{sales:[],purchases:[]}` arrays from an authorized upstream adapter. A future consumer will assemble **all** transaction sources before applying `projectDayBookRunningCash` and `projectDayBookWindow`. The source role comes from authenticated M04 context; `includeDeleted` is ineffective unless `isAdmin===true`. No direct user actor or filter can bypass this contract.

### Exact source parity
- Sales: original Invoice ID, POS description with optional Customer Phone, `Payment Type + ' Sale'`, Customer Name, Payment Status, Created By, created timestamp and source normalized time, original backdated/deletion fields, sale navigation/open/delete mapping. Missing `Payment Method` means legacy **Cash**. `Paid Amount` appears in cashIn only for Cash; bankIn only for Bank or Mobile Banking; due/no payment stays zero. Never classify a Store Credit or unrecognized method as cash or bank.
- Purchases: original Purchase ID, Supplier Name, Notes fallback “Stock purchase”, `Payment Status + ' Purchase'`, payment method fallback Cash, `Paid Amount` in cashOut or bankOut only for recognized method, original backdated/deletion fields and Purchase navigation.
- `dayBookRow_` signed `amount`, sourceModule/sourceId/openPage/openId/deleteModule/deleteId and key order exactly match the frozen source. Deleted source rows are omitted except Administrator includeDeleted, and are marked Deleted; this projector **does not** zero deleted row amounts because that is the GAS source output; downstream totals must skip all deleted rows. The source's unique Invoice ID audit is an upstream mandatory gate. This projector additionally rejects duplicate valid Invoice IDs and Purchase IDs rather than silently changing business identity.
- Sources are already normalized to canonical business YYYY-MM-DD for Date, canonical timestamp Created At and safeTimeOnly-derived Time (HH:mm:ss); reject malformed calendar dates, nonfinite source money, invalid scalar/accessors/inherited data and unsafe reference IDs. Do not perform timezone conversion, raw Sheets access, old GAS execution in production or hidden caching.

## Why not other alternatives
Running a D1 multi-table UNION now would depend on unreviewed financial table contracts and risk incomplete or double-counted business data. Reusing generic sales list/report projections loses original Day Book sourceType, deletion metadata and Bank/Mobile money direction. A minimal, independent, pinned-source projection can be tested exactly against the original for all supported source shapes while existing business posting remains unchanged.
