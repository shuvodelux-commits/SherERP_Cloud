## Small independently reviewable slice

The original source retires every non-deleted, nonzero `Session Open` (opening) or `Day Close Adjustment` (closing) cash movement for one exact Session ID. It replaces Credit/Debit with blank values and appends the source's retirement description; it does **not** remove row positions, IDs, `Type`, or `Reference`. Deleting a Session Open marker would corrupt later source-positional closing calculations. This PR proves that a **disposable local D1** copy can perform this bounded neutralization as one SQL-atomic test-only operation, without attempting to recreate the rest of the reconciliation posting kernel.

The test-only `m08_marker_*` STRICT tables independently model source cash rows (original immutable `legacy_row` physical order, per-tenant IDs, signed integer cents and soft-delete), Cash Session revision, token-backed staff/role authorization, immutable receipt and audit. A single guarded `INSERT ... SELECT` receipt claim validates the synthetic tenant/actor/token, live user/role/auth versions, revocation, session revision, phase and at least one eligible synthetic row. An `AFTER INSERT` trigger zeroes **all** eligible rows for the chosen phase and exact tenant+session reference, retains physical IDs/markers, advances the revision, and writes an audit. The whole statement must roll back on any update, revision or audit failure; idempotency is tied to a stable operation ID and intent hash, and conflicting submissions cannot create another phase claim. This is deliberately more transactional than the old GAS sequence of multiple `updateRowFields_` calls protected by LockService.

Use the existing M08 Workerd/D1 integration suite and its **unchanged** `wrangler.m08-opening-test.jsonc` and M08 CI workflow; avoid new shared Wrangler/workflow edits. The *new* M08-only files are `tests/fixtures/m08-marker-retirement-atomic-schema.mjs` and `tests/fixtures/m08-marker-retirement-atomic-contract.mjs`. Append isolated tests to `tests/integration/m08-d1-opening-explanation-workerd.spec.mjs` to reuse the dedicated local test harness; do not edit `src/db`, `src/rpc`, `src/index.js`, `migrations`, production modules or shared posting/auth code.

**Outside scope:** This operation does not validate selected real Cash Book explanation IDs, compute historical opening/closing discrepancies, handle full source-positional expected/variance recomputation, link real transactions or authorize a live financial RPC. It is one bounded test-only proof under issue #452; the full SQL-atomic source-positional reconciliation remains pending M03-owned production integration and M02/M04/M06 readiness. No real data or Cloudflare-hosted D1 can be touched.
