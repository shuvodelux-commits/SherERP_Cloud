# M06 — Sales Detail source-shaped read-only projection

**Date:** 2026-11-15. **Frozen source:** `Mohim_ERP@29aa4a5c7a7062a49e6bf4758beda3a8d62d9ff2`, `SalesManagement.gs::getSaleDetail`, `buildSalesInvoiceProfitMetrics_`, `canViewInvoiceProfit_`, and `Utils.gs::economicReturnLineAmount_`. Target `AGENTS.md`, `docs/MIGRATION_PLAN.md`, `docs/WORKSTREAMS.md`, ADR-007 apply.

## Purpose
The Sales screen needs the original `getSaleDetail` envelope for a clicked invoice: the already-ported historical posted invoice payload plus an economic returned amount/net sale and optional permission-gated original profit metrics. A return made after checkout must not silently alter original split tender/Customer ID. Bundle virtual parents are costed from the original physical component snapshots; vendor and purchased lot costs remain separate. Profit is private to the original Reports View or POS Purchase Price View capabilities.

## Contract
Add a **pure internal** `projectSalesManagementDetail(invoiceId,snapshot,{canViewSales,canViewProfit})`. Server-supplied, tenant-filtered `snapshot` carries all existing posted-invoice read model inputs (`sales,items,products,customers,paymentRows,settings,shop,settlement`), plus required arrays `returnItems,saleItemLots,vendorSourcing,bundleComponents`. These arrays represent **already authorized active Sales Return child rows**, net own-stock `SALE_ITEM_LOTS`, active Vendor Sourcing rows and immutable bundle component snapshots. The caller gets read permission from M04 server-side, never HTTP-supplied capability. `canViewProfit` is separately server-authorized, never inferred from a Party role. Source `getSaleDetail` returns `ok_(invoice)` data (no public RPC is added here). `projectPostedSaleInvoice` remains the canonical source-shaped invoice base.

**Returns:** source `economicReturnLineAmount_` uses raw `Line Total` when `Pricing Basis='NetAfterInvoiceDiscount'`, otherwise prorates by sale Grand/ Subtotal. Detail `returnedAmount` is the sum without intermediate rounding; `netSale = Number(grandTotal)-returnedAmount`. Profit source uses its own per-line `roundMoney_` accumulation and cost coverage checks; do not conflate the detail return display with the rounded profit ledger calculation. Profit cost = net `SALE_ITEM_LOTS` own-stock cost plus active `VENDOR_SOURCING` cost. Bundle cost coverage is physical component stock, not a phantom parent lot. Source `profitCostComplete` must remain false if coverage evidence is incomplete (do not claim exact cost). These are read-only projections, not new accounting state.

**Failure behavior:** missing trusted inputs/capabilities, ambiguous duplicate or deleted invoice header and invalid payment children fail closed. Private profit fields are entirely absent without cost permission, not zero-filled. Original invoice, Cash Session, Party, ledger, original source and UI are untouched. M03/M04/M05/M07/M08 retain atomic writes, read permissions, FIFO/reversal and Customer settlement responsibilities.
