# M09 Reports print and filter freshness control — nondeployable handoff

**Workstream:** M09 Issue #431. **M01 integration owner:** Issue #25. **Base:** `main@76cca6a9b107603cc19a727a6907c7602cddd011`. **Dependency:** merged PR #571 Playwright visual evidence, preserved frozen `legacy/source/reports.html` and `Reports.gs::reportRange_`.

The original Reports page maintains `rptState.loaded[tab]` as a boolean keyed by six tabs. Date edits do **not** invalidate it until Run/Today/This Month is pressed. Consequently a user can edit From or To, navigate to a previously loaded tab, and see totals computed for an earlier filter while the UI displays a new date. The original Print handler also immediately invokes `window.print()` even if the active tab has not successfully loaded its report; a 501/failed loader can produce a document full of placeholders. This is a **user-interface consistency risk**, not a financial posting or source-data error.

Create a tiny **pure, internal, M09-only** `inspectM09ReportControlState(input)` projection accepting the active original tab key, explicit `reportLoaded` and `requestPending` booleans, the current From/To, and the last successful From/To. Return only fixed status codes, `printPreviewEligible`, `needsRun`, `periodApplies`, `ready:false`, `authorized:false`. The latter two flags emphasize this helper is not an auth or data-read gate. For the four period reports Sales/Purchase/CashBank/Profit, the date window must be two valid ordered YYYY-MM-DD calendar dates, must match the last successful period, and have an active successful result without an in-flight request. The original source swaps reversed dates internally; the proposed *UI* policy instead blocks printing until the user explicitly corrects or runs a canonical date window. Do not change the frozen report normalizer or finance calculations. The two snapshot reports Stock/Balance Sheet do not depend on date filters, but still need a successful current tab result to print.

Reject accessor/prototype input without executing getters; output only the tab/status and boolean indicators, no source IDs, dates, financial amounts or customer names. Tests use frozen original report HTML as a tab-key oracle. Separately run a Playwright browser audit demonstrating baseline Print and stale cache behavior on the actual compiled legacy UI with synthetic stubs, without triggering live financial APIs. If feasible, provide an isolated nondeployable interaction proposal, not automatic production frontend wiring. M01 owns any reviewed integration in source-preserving frontend assets; no edits to `legacy/source/**`, `src/db/**`, `src/rpc/**`, Worker, posting, permissions, schema or live reports.
