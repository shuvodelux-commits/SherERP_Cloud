# M02-P — Fail-Closed Gross Party Source Rehearsal Gate

**Date:** 2026-11-15. **Frozen source:** Mohim_ERP@29aa4a5c7a7062a49e6bf4758beda3a8d62d9ff2. **Authority:** AGENTS.md, ADR-007 unified Party/separate accounts, docs/WORKSTREAMS.md and docs/M03_PARALLEL_READINESS.md (parallel preparation only).

## Problem

Merged #162 can approve only the *supplied* complete and unchanged Party source snapshots and reviewed identity claims; merged #184 separately validates the *supplied* FINANCE_TRANSACTIONS original 20-column export and independent row count. The existing pure `prepareGrossPartyBalances` derives owner, lender, borrower, customer, supplier and vendor gross account checkpoint amounts, but can be called with truncated Finance rows, incomplete Party master sources, or stale identity decisions. Two independently green checkers are not a safe chain when a future offline operator neglects one. Overlapping M02-P PRs own exact finance source ID coercion (#180/#181/#182), Party readback and human-approved link bindings; they must not be edited.

## Decision

Add an **internal-only pure coordinator** `validatePartyGrossRehearsal({reviewedRows,reviewedHeaders,candidateRows,candidateHeaders,approvedGroups,financeRows,financeHeaders,declaredFinanceRows})` in a *new* `src/party/gross-rehearsal-gate.js`, reusing only existing three established pure functions:
1. `validatePartyImportCandidate` validates **both** frozen five-master exports, row completeness, original source changes and explicit human-reviewed merge claims. It only validates the caller-supplied review evidence; it cannot authenticate a reviewer.
2. `validateFinanceTransactionExport` requires **exact** original Finance transaction column headers, independently declared row count, all source columns including deleted history, literal original source IDs and valid active Amount.
3. Run the existing `prepareGrossPartyBalances` **only if both first checks are clean**, using the unchanged candidate original rows, approvedGroups and complete financeRows. No preflight is run on an incomplete, changed or pending-review source. The signed current/advance and separately historical opening amounts remain in the **private** preflight, not returned by this coordinator; vendor payable/receivable, Customer/Supplier receivables and advances, Owner/Lender/Borrower balances remain gross and independent. An unknown Finance type, missing Person source link, incompatible role or negative vendor direction may still fail at the gross stage.
4. Return only `{formatVersion:1,partySourceValid,financeExportValid,grossPreflightChecked,grossDesignReviewClear,offlineGrossRehearsalClear,counts:{party,finance,gross},issues}`. The `counts.gross` object is `null` until the final stage is actually evaluated; on evaluation it contains **only** `proposedParties`, `sourceFinanceRows`, `deletedFinanceRows`, `pendingIdentityReviews`, `currentCheckpointCount` and `historicalOpeningCheckpointCount`. Never return `grossCurrentTotalsMinor`, `grossOpeningTotalsMinor`, `currentCheckpoints`, `openingCheckpoints`, source IDs, Party IDs, named reviewer evidence, amounts, source names/phones or raw SQL/results.
5. Issues are fixed-code counts, `{stage,scope,code,count}`. Preserve fixed original Party validator stages and source group names; Finance stage/scope `FINANCE_EXPORT/FINANCE_TRANSACTIONS`; Gross `GROSS_ACCOUNT/GROSS_ACCOUNT` codes from a strict whitelist of known source preflight reasons. A skipped gross stage has `GATE/GROSS_ACCOUNT/GROSS_PREFLIGHT_SKIPPED`; must never be interpreted as a pass. Aggregate duplicate gross reasons, sort deterministically.
6. Source metadata `financeHeaders`/`declaredFinanceRows` must come from trusted offline export tooling. This coordinator cannot verify its authenticity. All outer shape or downstream errors must fail closed with fixed `Party gross rehearsal unavailable` and no source values. `offlineGrossRehearsalClear` means **only** internal data-shape/review-consistency and gross checkpoint readiness for accounting *design review*; it is **not** identity authorization, real D1 proof, persisted approval_ref, ledger parity, production readiness, or cutover permission.

## Scope and limitations

Exactly **four new files**: this spec, Superpowers plan, focused Node synthetic tests and one pure module. No changes to existing source, original GAS/UI, shared Party/Finance preflight, auth/RPC, SQL migrations, D1, Cloudflare, cash/bank, balance posting or finance settlements. Source IDs used in private intermediate plans retain original representation. No automated money movements or source record changes. KISS; fail closed; no new dependencies. GitHub-only Superpowers RED first and GREEN; exact-head CI evidence; leave draft unmerged for owner.

**Rollback:** revert PR. No data migrations or changes. `PARALLEL-MODULE-READY=false` remains.
