# M09 source-manifest count binding for historical return lineage

**Workstream:** M09 Reports evidence only. **Issue:** #431; coordination issue #456. **Base main:** `5ac51572cc3220480cd00841230f07df1c56d924`. **Dependency:** merged #508 at `19698276b4fb5f63c7ae5f98b31f3d4a81820a24` (44/44 exact-head CI). **Frozen GAS:** `Mohim_ERP@29aa4a5c7a7062a49e6bf4758beda3a8d62d9ff2` — `Reports.gs`, `DeleteEngine.gs`, `Utils.gs`.

## Defect
`evaluateM09ReportsSourceEligibility` checks sourceRows versus importedRows within each reviewed receipt. Separately, `evaluateM09ReportsLineageEvidence` calls the pure parent-child Sales/Purchase return audits over full historical source-shaped arrays. The composer never binds those original arrays to the reviewed receipt counts. Its existing pristine tests even supplied 1 row in every Sales/Purchase/Return input while attesting zero sourceRows and importedRows, yet obtained `evidenceComplete:true`. This does not authorize any live report (`ready:false` is invariant) but creates misleading pre-activation evidence.

## Design
Reuse the existing composer, its source-eligibility result and the already reviewed Sales/Purchase lineage auditors; do not invent a second report-read framework. For each snapshot, validate the complete historical `allSales`/`allPurchases`, `returnHeaders`, `returnItems` **array lengths** against the corresponding reviewed `sourceRows` receipt for `SALES`, `SALES_RETURN`, `SALES_RETURN_ITEMS`, `PURCHASES`, `PURCHASE_RETURN`, `PURCHASE_RETURN_ITEMS`. These are the raw source-shaped arrays **including soft-deleted rows**; never count only active parents/children. Existing evidence checks independently require importedRows to match sourceRows, provenance and deletion states to be reviewed.

Only after a snapshot passes the existing shape/accessor safety auditor may the composer compare its array lengths. Continue to block missing or malformed snapshots with fixed original `*_LINEAGE_MISSING/INVALID` codes; original manifest missing/unreviewed groups remain fail-closed. The composer must not invoke accessor properties. On mismatches append fixed redacted `<SOURCE_GROUP>_SOURCE_ROWS_MISMATCH` codes to the per-report `lineageBlockers`; never output actual row counts, source IDs, amounts, names or underlying exceptions. Sales groups affect Sales and Profit only; Purchase groups affect Purchase and Profit only. Stock, Cash/Bank and limited Balance Sheet preserve independent status. Mixed integrity/lineage defects are both reported.

Even with complete synthetic evidence the result is still `ready:false` and `AWAITING_AUTHENTICATED_D1_GATE`; this is neither a real imported-source digest nor authorization/tenant identity proof. Do not modify `src/db/**`, `migrations/**`, `src/rpc/**`, `src/index.js`, Worker bindings, posting, legacy GAS, UI, report calculations or financial source data. Later activation requires M02/M03/M04/M05/M07/M08 evidence plus M10/M11 acceptance.
