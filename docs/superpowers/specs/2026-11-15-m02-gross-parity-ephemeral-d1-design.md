# M02-P — Isolated Real D1 Checkpoint Parity Rehearsal (2026-11-15)

**Frozen original:** Mohim_ERP@29aa4a5c7a7062a49e6bf4758beda3a8d62d9ff2. **Authority:** AGENTS.md, docs/WORKSTREAMS.md, docs/M03_PARALLEL_READINESS.md, ADR-007. **Prerequisite:** merged #202's pure `src/party/gross-checkpoint-parity.js` contract.

## Purpose
Merged #202 proves the private source gross checkpoint comparator with supplied in-memory snapshots but has no evidence that a real local Workerd/D1 SELECT result could flow through the same identity, account kind, current/opening basis and exact minor-unit reconciliation without silently netting roles. The actual financial account D1 schema is **not approved** and deliberately absent from migrations. We need isolated integration evidence, not a new account schema or production path.

## Decision
1. Add **test-only** `tests/fixtures/m02-gross-checkpoint-d1-reader.mjs` exporting `reconcileSyntheticGrossCheckpointsD1({DB,preflight})`. This never enters `src/`, deployed Worker, any RPC, or migration.
2. Use the already approved local Workerd harness `wrangler.m02-plan-test.jsonc` on **ephemeral local D1** and apply the unchanged two real migrations. Then the test fixture itself creates a uniquely prefixed temporary-only **`m02_test_checkpoints` table** with seven source checkpoint fields; it is not a reviewed future Party account schema, has no journal/settlement/writer implications and is never deployed.
3. The test helper runs existing pure `reconcileGrossPartyCheckpoints` with empty synthetic readback **before** any D1 access. If the source plan is blocked or internally forged, return the existing redacted `sourcePlanValid:false` report and never access DB. If ready, require a D1-style binding, do exactly one batch of two fixed, read-only `SELECT` statements (current and historical opening scoped by literal fixed basis), strictly validate both success envelopes, and translate snake-case D1 columns via SELECT aliases into the existing private checkpoint row shape. Pass those rows to the approved pure comparator; only its **redacted** fixed-code count report escapes the helper. Never echo raw error text or private values.
4. Use real local D1 test rows only from **synthetic** `prepareGrossPartyBalances` preflight; the tests may insert/reset into the **test-only** table but the helper itself never writes. Test full gross account parity for the same reviewed Party, one-cent drift, missing/extra/duplicate account, current versus historical opening movement, source ID/Party ID mismatch and deleted Finance history, plus D1 failure, skipped DB on invalid plan, no new production tables, no exposed Worker routes and no input mutation.
5. Add an isolated PR-only/no-secret GitHub Actions workflow running this exact Workerd/D1 suite with pinned Wrangler; not a deployment workflow. Use Superpowers TDD: plan/spec + tests/workflow first, observe expected RED missing fixture module on GitHub, then add minimal GREEN helper, verify all exact-head CI and leave draft/unmerged.

## Non-goals / strict guardrails
No financial account D1 schema, remote/staging/production D1 changes, migration SQL, API/RPC, live Worker binding, original GAS/UI, cash/bank, automatic cross-role netting, approvals or cutover. This test proves local D1-shaped **test-only** checkpoint readback, **not** real production account parity. `PARALLEL-MODULE-READY=false`. Rollback by reverting new-only PR.
