# M08 — Opening reconciliation source-validated local D1 preview

**Issue:** #448 | **Pinned authority:** Mohim_ERP `29aa4a5c7a7062a49e6bf4758beda3a8d62d9ff2`, `CashReconciliation.gs`. **Dependency:** merged #437, #404, #370. Owner workflow: GitHub-first / Superpowers TDD / KISS.

## Reviewed design

Opening reconciliation is an **explanation**, not a fresh financial posting. The first Session Open baseline has no eligible opening discrepancy. Later sessions compare Opening Cash with the last **previous Closed session having an explicit counted amount**, ordered by opened-at chronology. A positive or negative difference can be explained only by existing real Cash Book entries matching the required Cash In/Out direction and exact cent-rounded sum. Entry IDs are normalized per frozen source, and missing, deleted, synthetic, zero-signed, cross-session or cross-phase linked entries must fail before any mutation. Entire tenant Cash Book evidence must be considered, even when UI shows only the latest 250 candidates.

The existing `validateCashReconciliationExplanation` already has pinned-GAS VM tests and remains the **sole validator**. Add a small `tests/fixtures/m08-d1-opening-explanation-preview.mjs` test-only adapter that reads separate disposable `m08_opening_sessions` and `m08_opening_cash` strict tables through one tenant-bound D1.batch read. Storage retains original physical row indexes and exact signed integer cents; source-shaped records retain opened-at session chronology and both phase's linked IDs. Use the existing validator for opening. The adapter must never write, authorize a user, or expose a Worker route: it is synthetic fixture access only.

Run actual real local Workerd/D1 integration tests that also call the **original pinned GAS `saveCashReconciliationExplanation`** in a VM as a source oracle (only synthetic stubs; capture original attempted writes). Compare accepted `{state,requiredDirection,requiredAmount,entryIds}` and exact source errors. Assert before/after unchanged D1 snapshots for every accepted/rejected case, including tenant isolation, historical baseline refusal, previous counted zero vs missing, two-entry Cash In and Cash Out, one-cent variance, wrong sign, missing/deleted/synthetic, cross-phase allocation, unselected candidates beyond 250, malformed input/ambiguous import and 404 test Worker.

**Safety boundaries:** No actual D1 finance schema/migration, no RPC, no Cloudflare production/staging binding, no real business data, no original GAS change, no effective adjustment retirement, no approved financial writer. This only proves a **read-only opening explanation decision** on a consistent local synthetic D1 snapshot; a future posting writer must revalidate within an atomic SQL guard and retain historical Cash Session semantics.
