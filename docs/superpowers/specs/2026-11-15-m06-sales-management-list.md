# M06 Sales Management list — source-parity read-only design

**Frozen source:** `Mohim_ERP@29aa4a5c7a7062a49e6bf4758beda3a8d62d9ff2` — `SalesManagement.gs::getSalesManagementList`, `buildSalesInvoiceProfitMetrics_`; `Utils.gs::duplicateSalesInvoiceIdMap_`, `economicReturnLineAmount_`, `safeDateOnly_`, `safeTimeOnly_`; `CashSession.gs::findSessionForTimestamp_`. Current authority: `AGENTS.md`, `docs/MIGRATION_PLAN.md`, `docs/WORKSTREAMS.md`, ADR-007.

## Intent

Preserve the source Sales-screen list (not the M09 analytics report): one row per active Sales header, showing invoice/customer, date/time, total, paid/due/current settlement, return status, economic returned amount/net sale, duplicate warning, historical Cash Session editability and separately permitted private profit. Do not infer Customer/Party identity from phone/name. No live Sales/Cash/Bank/stock/accounting posting, RPC, worker preview bindings or UI changes.

## Trusted inputs and authority

Export `projectSalesManagementList(snapshot,{canViewSales,canViewProfit})`. `snapshot` contains trusted tenant-scoped arrays `sales` (active Sales headers, duplicates deliberately retained), `items`, `returnItems` (M07 active return child rows, after filtering active parent return headers), `sessions`, `bundleComponents`, `saleItemLots` (net quantity after returns), `vendorSourcing` (raw rows with original deleted flags), plus a trusted server-side `settlementsByInvoice` map. M03/M04/M05/M07/M08 independently verify source row scope and settlement reconciliation; the map contains current `paidAmount,dueAmount,customerCreditUsed,paymentStatus` snapshots keyed by the **original Invoice ID** only for tracked Customer IDs with original Due Amount >0.004. Missing required settlement evidence rejects instead of presenting stale due. No Party-role netting. M04 must authorize Sales View; profit only when server authorizes the frozen Reports View or POS Purchase Price View capability. Browser must never supply these capabilities or current settlement data.

## Source semantics

- Preserve frozen sort `String(date + ' ' + time)` descending; canonical trusted dates/times are `YYYY-MM-DD` and `HH:mm:ss`. Original duplicate IDs remain visible with `duplicateInvoiceId:true`, `returnStatus:'Integrity Error'`, `returnedAmount:null`, `netSale:null`, `editable:false`, no settlement or profit projection. Do not guess which historical child belongs to which sale.
- Sum original `SALE_ITEMS` quantities by invoice and Product ID. `returnItems` are original ACTIVE return children. For each item, `Pricing Basis='NetAfterInvoiceDiscount'` uses raw return Line Total; legacy blank value prorates by parent Grand/ Subtotal. Return is `Fully Returned` only when EVERY originally sold product has returned quantity >= sold; otherwise `Partially Returned` when positive economic returnedAmount; else `No Return`. Source `editable` refuses ANY return record, historical Closed Cash Session or duplicate ID; the most recently opened session no later than original Created At wins. Read eligibility does not authorize a later edit.
- Current settlement is used only for tracked original Customers with original Due>0.004 and unique headers. Cash/anonymous sales retain original Paid/Due/Payment Status and `customerCreditUsed:0`. Checkout split tender remains unchanged. Disallow missing, malformed, nonfinite settlement evidence rather than inventing a reconciled balance.
- Reuse the **existing M06** `sourceProfitMetric` implementation from `sales-management-detail-read.js`; export it solely as an internal pure helper and adapt source list names without another cost calculator. Profit requires explicit capability, unique invoice, and complete cost-evidence arrays; preserve `profitCostComplete:false` when FIFO/vendor cost evidence incomplete.
- Inputs are already authorized/tenant-filtered source-shaped rows; reject missing arrays, accessors or unexpected non-plain row objects. No writes or mutation. Date/time are canonical D1 inputs; reject bad formats rather than timezone-guess.
