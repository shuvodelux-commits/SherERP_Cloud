## Exact original display behavior
- **Bank Transfers**: one original header row per `BANK_TRANSFERS` source record, **not two bank ledger entries**. `referenceNo = Transfer ID || ''`, `sourceId = Transfer ID || ''`, `ts = Created At || Date`, `date = safeDateOnly_(Date)`, `module='Bank Transfer'`, `transactionType='Bank Transfer'`, `party = (From Account Name||'') + ' → ' + (To Account Name||'')`, `description=Notes||'Transfer between accounts'`, `paymentMethod='Bank'`, `createdBy=Created By||''`, `status='Active'`. Original block does not inspect deleted/status/backdated metadata; **do not invent** any such values; use the `dayBookRow_` defaults (`isDeleted:false`, `isBackdated:false`, `backdatedDays:0`, blank audit). `bankIn=bankOut=cashIn=cashOut=0`, signed amount zero, no double counting. `openPage='bank'`, `openId=Transfer ID||''`, `deleteModule=''`, `deleteId=Transfer ID||''`. A single legacy blank Transfer ID is preserved in exact-source output; nonblank IDs must be unique/safe.
- **Stock Adjustments**: only `STOCK_MOVEMENT` rows whose **case-sensitive** `String(Type||'').indexOf('Adjust') !== -1`; no false positives for non-Adjust Sale/Purchase events. `ts=Date` (already normalized as a shop-local date-only or timestamp), `date=safeDateOnly_(Date)`, `referenceNo=Movement ID`, `module='Stock Adjustment'`, `transactionType=Type||'Stock Adjustment'`, `party=Product Name||''`, `description=(Notes||'Stock adjusted')+' ('+(qtyIn?('+'+qtyIn):('-'+qtyOut))+')'` with `qtyIn=Number(Quantity In)||0`, `qtyOut=Number(Quantity Out)||0`. This means **zero quantity prints `(-0)`**, the exact frozen behavior; do not infer inventory value. `paymentMethod=''`, `status='Active'`, `sourceModule='Stock Adjustment'`, `sourceId=Product ID||''`, `openPage='products'`, `openId=Product ID||''`, `deleteModule=''`, `deleteId=Product ID||''`. Original stock adjustment section does not include `Created By`/deleted/backdated audit; defaults remain blank/false/zero. All Cash/Bank columns and signed amount exactly zero even with large quantities; do not treat stock movement as physical cash.
- Source section order must be all Transfer rows then filtered Stock Adjustments. Preserve original exact `dayBookRow_` property **order** and output (no synthetic rounding, balance, filter, sort, or replacement keys).

## Input validation / trust boundary
- Snapshot must have **both complete arrays** (not one missing). Plain own-data records and plain arrays only; no accessors, sparse/inherited records, nonfinite numeric fields, or hidden exotic objects. Validate transferred source IDs for safe non-prototype colliding nonblank values and duplicate **nonblank** Transfer IDs. Stock Movement IDs must be nonblank safe and unique for deterministic source navigation; Product ID may be blank, as frozen source permits, but nonblank must be safe. Exact amount/quantity fields must be finite where relevant. Validate shop-local `YYYY-MM-DD` and `YYYY-MM-DDTHH:mm:ss` without timezone parsing (the source's GAS `safeDateOnly_` handles serialized Sheets dates; upstream normalizer must provide shop-local dates). Cash/Bank and other posting fields are not inferred from input.
- No `isAdmin` or includeDeleted flag: these source blocks do not apply source deletion filtering. Do not add a privilege bypass or fake approval. The containing Day Book RPC must be authenticated/tenant-authorized upstream by M03/M04.
- Do not calculate/account transfer in/out from `BANK_BOOK` here: the previously merged Bank dedup projector suppresses header-owned bank entries. Only complete authorized orchestration may compose that.
