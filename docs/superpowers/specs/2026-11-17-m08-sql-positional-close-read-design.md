## Independently approved M08 scope

The existing D1 adapter reconstructs source-shaped arrays and calculates expected closing cash in JavaScript. This new **read-only** test-only fixture calculates the same expected/variance values in SQL through **four parameterized SELECTs in one transactional D1.batch** on one consistent local D1 snapshot. Workerd's SQLite resolver rejects the original deeply nested single-statement CTE query; the read-batch form keeps the accounting calculation in SQL while avoiding the depth limit. It tests source Cash Book physical `legacy_row` order (never `Date`), the first matching `Session Open` and next marker boundary, ignored deleted/synthetic entries, opening-linked exclusion, cross-phase/session linked usage, late closing reattribution and counted-zero vs missing-count variance. It rejects duplicate imported nonblank IDs, duplicate session IDs and ambiguous Session Open markers. The SQL batch never writes Cash Book rows, creates links or authorizes a financial actor. It reads source sessions, duplicate Entry IDs, physical markers and an SQL-aggregated movement/variance.

**Canonical linked-ID storage precondition:** The synthetic imported Session records must store linked IDs as either an empty string or a JSON array of strings. The original Sheets source permits CSV and newline forms, which the existing source parser accepts; a future approved M02 importer must normalize those forms before an SQL transaction can use `json_each`. This proof fails closed on malformed raw strings and non-string JSON elements rather than guessing or applying a partial link. Duplicate IDs in a JSON array are deduplicated just as the pinned source parser does. It deliberately does not claim full import compatibility.

**Implementation:** add `tests/fixtures/m08-sql-positional-close-read.mjs` (only M08-owned test fixture), extend `tests/integration/m08-d1-positional-cash-workerd.spec.mjs` using the existing fake M08 local Wrangler binding and dedicated PR-only Workerd workflow (unchanged). Run the pinned GAS VM and existing pure source projection on identical synthetic data, then compare the SQL result. Use exact integer cents and reject overflow. Assert no changes to either disposable D1 table after successful and rejected reads. All shared `src/db`, `migrations`, `src/rpc`, Worker entry, auth, ledger kernel, public bindings and common CI files remain untouched.

**Limitations:** A transactional multi-SELECT SQL read proof is **not** an atomic cash-session posting operation. Applying it to Cash Session expected/variance, adjustment neutralization, linked-entry claims, immutable audit and auth/revision checks in one transaction requires a separate M03-owned reviewed integration proposal and actual real schema. No live financial endpoints or remote D1 changes are authorized by this PR.
