## Original source fidelity
A Purchase Return is a new linked return, never an edit of original Purchase. For the Cash method it reduces **the original purchase's** available source lot and product stock, writes one outgoing stock movement, and records a **Cash Book Credit (cash inflow)** for the economic return amount; it does **not** change Supplier Current Due. Even a fully unpaid purchase cannot use Cash refund. Total Cash return must be <= **verified original Cash paid** minus all earlier active Cash Purchase Return refunds for that purchase. The source may have later separate supplier settlements, but synthetic M05 has only immutable original `paid_paisa`; do not infer unknown later settlements. Multi-lot FIFO by purchase date then Lot ID and legacy fallbacks are **not covered** in this one-owned-SKU/one-original-lot proof.

The synthetic original purchase has `qty`, `unit_cost_paisa`, `discount_paisa`, `grand_paisa`; the effective return price includes the invoice discount. This proof requires `grand_paisa * returnUnits` exactly divisible by original quantity in paisa to avoid claiming unproven fractional-cent/rounding parity. Reject unsupported cases. It requires exact original `lot_id='LOT-'||purchase_id` from the M05 purchase posting trigger; a foreign supplier or unrelated purchase lot cannot be reduced, even if shop stock elsewhere is available. Return quantity can never exceed remaining original source lot or total original bought-unreturned quantity. No Cash Session if closed, anonymous/ambiguous supplier source or stale link.

## Transaction boundary
Test-only `createSyntheticD1PurchaseCashReturnContract(DB).post(input)` validates strictly trusted `tenantId,actorId,purchaseId,returnId,operationId,sku,lotId,originalHash,units,refundPaisa,reason`. The M03 SHA-256 operation fingerprint records source, actor, amount and lot. Results `COMMITTED|REPLAY|CONFLICT|DECLINED`, with uncertain D1 error `NEEDS_REVIEW`. In the same guarded SQL INSERT transaction: check M05 original parent and source item/lot/movement, active Cash Session, verified supplier link, original paid amount and prior Cash refunds, exact unit-discount price and stock; AFTER INSERT trigger decrements the exact source lot and product stock, logs linked outgoing movement and one **Cash inflow**. Late movement or Cash insert fault must roll back return receipt and both stock mutations. Concurrent duplicate/stale claims post at most once. No Party cross-role offsets or Supplier ledger changes. No public HTTP/RPC exposure.

## Scope / noncoverage
Only one standard owned SKU line and original single M05 lot, whole integer units, original purchase payment amount (no later settlement reconciliation), strict exact-paisa invoice discount, Cash refund only. No Supplier Credit, multi-line M05 purchase stock allocation, source FIFO multi-lot selection, combined units, vendor/OVERSOLD, backdates, M04 auth, real M05/M08 supplier obligation ledger, correction/edit/delete, original UI, public Worker route or live D1 migration.
