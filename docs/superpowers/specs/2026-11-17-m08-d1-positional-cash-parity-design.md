## Design

The frozen GAS calculation identifies a physical source Cash Book interval from a matching `Session Open` marker to the next `Session Open` marker in array order, not Date order. It ignores deleted and synthetic postings, opening explanation entries and entries attributed to other sessions. A linked closing explanation outside that interval is added exactly once. It distinguishes explicitly counted zero from missing closing count and rounds cents per source. This behavior already has pure-function source parity in `src/modules/m08-closed-session-cash-recalculation.js` and its VM oracle tests; this slice tests the missing **Cloudflare D1 storage/chronology boundary**.

A disposable `m08_positional_cash` table carries `(tenant_id,legacy_row)` physical source order, original Entry ID/Type/Reference, signed cent columns, date, soft delete. A disposable `m08_positional_sessions` table carries `(tenant_id,legacy_row)`, source session ID/status/opening and counted cents, opening and closing linked IDs. The test-only query uses a single `DB.batch` read transaction, binding tenant scope to BOTH selections and sorting by `legacy_row`. Its projection maps physical rows into source-shaped records and calls existing read-only `recalculateClosedSessionCash`, without inventing a new accounting algorithm. Return only `{sessionId,recalculated}`, with `recalculated:null` on nonclosing/missing marker; fail closed on malformed inputs and duplicate imported IDs.

Workerd local tests load the **pinned GAS source directly** via `loadPinnedGASFunctions`, compare each read projection with the exact oracle for intentionally shuffled dates and insert order, external linked use, late/inside closing explanation, opening exclusion, negative/zero/missing amounts and cross-tenant duplicates. Every test verifies that read operations leave all D1 tables unchanged and test Worker routes remain 404. The adapter is fixture-local, not imported by production Workers/RPC. No current scheme, original Sheets source, cloud binding or financial operation changes.

**Remaining blockers:** A successful read parity proof does not provide a single-transaction guarded write using this positional algorithm. Real Cash Book import and stable `legacy_row` provenance, authentic tenant/session, transaction/auth state, source opening cash correction, concurrent financial accounting and owner-approved backup/cutover remain outside this PR.
