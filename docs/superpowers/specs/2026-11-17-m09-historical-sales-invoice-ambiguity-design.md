# M09 original historical Sales invoice ambiguity — design

**Lane:** M09 pure report source evidence. **Base:** main `40f6ae4b9cb6f17bbd6fed72a3455ba356ffed02`. **Issue:** #431; coordination #456. **Dependency:** merged PR #522 source-row count proof. **Pinned oracle:** `Mohim_ERP@29aa4a5c7a7062a49e6bf4758beda3a8d62d9ff2` `Utils.gs::duplicateSalesInvoiceIdMap_/assertUniqueSalesInvoiceIds_`, `DeleteEngine.gs::isDeleted_`, `Reports.gs::getSalesReport/getProfitReport`.

## Root cause
The original Sales Report selects active invoices but checks their normalized IDs against *all* historical Sales source rows, including soft-deleted ones: `assertUniqueSalesInvoiceIds_(selected,context,allSales)`. The existing `auditM09SalesReturnLineage` instead skips deleted rows before collecting invoice IDs and counts active IDs by untrimmed original values. A deleted historical collision with an active invoice (or two active invoice IDs differing only by surrounding spaces) could leave `lineageComplete:true` while the original report would refuse a financially ambiguous invoice-linked result. A future authenticated report must not infer which history owns the original Invoice ID.

## Scope & choice
Extend the already merged, pure M09 Sales Return source lineage audit rather than adding another diagnostic or touching the financial report projector. Preserve raw original Invoice ID references for parent-child Return linkage checks; only the *duplicate detection key* is normalized with `String(id).trim()`, matching the original frozen helper. Count normalized IDs across all source Sales, and separately count active normalized IDs. When two active rows share an ID, retain existing `DUPLICATE_ACTIVE_SALE_INVOICE`; otherwise when a single active ID aliases one or more historical deleted rows, report the fixed redacted `AMBIGUOUS_HISTORICAL_SALE_INVOICE_ID`. Purely deleted duplicate IDs without an active invoice do not cause a report ambiguity. Invalid active IDs continue returning the original invalid-ID code. Prefer one source issue per normalized key class; never output IDs, row counts, names or financial values.

Tests execute the *actual frozen* duplicate helpers and deletion helper in a VM rather than a copied oracle. Cover exact deleted duplicates, whitespace-normalized historical aliases, active normalized aliases, deleted-only duplicates, simultaneous cases, redaction and non-mutation. The entire audit remains `{ready:false,lineageComplete,status,issues}` with no source reader, D1, SQL, public RPC, posting, finance formula, UI or original source changes. M03/M04 authenticated source, M05/M07/M08 historical finance parity, M10 staging and M11 cutover remain separate, blocked dependencies.
