Customer/Supplier payment and customer advance refund parity is still **open draft PR #381** at this task's initial GitHub check. These modules are pure display projectors, not full D1 source feeds. Chosen approach is an independently reviewable, additive, source-shaped `projectDayBookExpenseFinanceRows({expenses,financeTransactions},isAdmin=false,includeDeleted=false)`, operating only on **complete already-authorized source rows** with normalized local shop date/timestamp. It does not read D1, mutate cash/accounting or alter original UI/RPC.

## Exact GAS parity
**Expense**: original Expense ID, Category Name/default Expense, Ledger Name, Description, Created By, shop Date and Created At, payment method default Cash, amount in `cashOut` only for active Cash, in `bankOut` for active Bank/Mobile Banking; other methods move no money. **Cancelled and deleted expense rows display ZERO money, even when admin views deleted**; deleted status takes precedence over Cancelled. Original Expense navigation `expenseList`, delete dispatcher `expense`, sourceId, metadata and signed amount preserved.

**Finance**: original `Finance ID`, Person, Description = `Notes || finance type label || 'Finance entry'`, optional ` — Reference No`, date `Created At || Date`, Created By, financeLedger navigation/finance delete dispatcher. The *six* non-opening source types are Owner Investment (Owner Credit, in), Owner Withdrawal (Owner Debit, out), Loan Received (Lender Credit, in), Loan Repayment (Lender Debit, out), Borrower Loan (Borrower Debit, out), Borrower Repayment (Borrower Credit, in). Original `FINANCE_TRANSACTION_TYPES` also holds *three opening types* (Opening Owner Capital, Opening Loan, Opening Borrower Loan); these **always** report `paymentMethod:''` and zero cash/bank movement (historical, not live cash), even if a source record contains `Payment Method:'Cash'`. An unknown finance type is original label as-is, no money. Cash moves in/out by type direction, Bank/Mobile Banking bankIn/bankOut, unsupported method zero. Deleted Finance source display amounts remain source-shaped for admin view but are **excluded from downstream totals** by `projectDayBookWindow` (unlike deleted Expense, whose source row has zero money). No auto-netting of Owner/Lender/Borrower roles.

**Output and security:** preserve exact `dayBookRow_` property key order, status/deleted/backdated metadata, openPage/openId/deleteModule/deleteId and source order Expense then Finance. Only trusted `isAdmin && includeDeleted` can view deleted source rows. Validate trusted own-data plain object arrays (no sparse slots/getters/inherited exotic prototypes), unique source document IDs per module, safe IDs, canonical business-date and timestamp strings, finite numeric source money, canonical scalar record shape; fail closed. Source `Amount` blank->0. Dates already local/shop-normalized; do not parse timestamps in UTC or use ambient time.
