## Rationale / selected design
Merged #361 produces source-shaped Sales/Purchase rows; #350 computes actual Cash Book drawer balances, #342 suppresses duplicate Bank Book documents, and #329 filters/totals. The complete authorized M03/M04/M05/M07/M08 D1 Day Book transaction feed remains unavailable. Implementing the full D1 union now would mix unfinished Returns and Supplier Ledger schemas with M07's parallel reversal work (#363), and a guessed refund method would misstate cash. **Chosen minimal M09 scope:** one pure internal source-shaped projector of both Return documents from already authorized, normalized and **complete** source arrays. It never posts, reverses, reads D1, or affects M07 native Returns.

## Interface and exact original behavior
`projectDayBookReturnRows({salesReturns,purchaseReturns,supplierLedgerRows},isAdmin=false,includeDeleted=false)` returns new original-shaped Day Book rows with Sales Return block first, then Purchase Return. Require **all three** arrays. Supplier Ledger MUST be the entire source-equivalent ledger (not merely payment rows, and not filtered for deletion): original source derives `Purchase Return Credit` by exact `Type === 'Purchase Return Credit'` with matching `Reference === Purchase Return Return ID` even if that ledger row is marked deleted. With a credit reference, Purchase Return is noncash `paymentMethod:'Supplier Credit'`, `cashIn:0`, `amount:0`; without one, it is `Cash` and `cashIn` equals Total Return Amount. The original has **no stored Purchase Return Refund Method**; never invent a bank refund or infer one from a separate bank entry.

Sales Return derives `method = Refund Method || 'Cash'`. Exactly `Cash` means `cashOut = Total Return Amount`; exactly `Bank` means `bankOut = Total Return Amount`; other methods (including `Mobile Banking` in the frozen source) are displayed as `Store Credit` without cash/bank movement. Sales Return `transactionType` nevertheless preserves the original method text + ` Refund`. Purchase Return `transactionType` stays `Purchase Return`, with signed headline amount positive only for real cash inflow. Preserve source Return ID, originating Invoice/Purchase ID as `openId`, `Processed By`, date/ts, reason-extended description, source module/open page/delete mapping, backdated/audit fields and original complete `dayBookRow_` field order. Note `Purchase Return` has no original Day Book delete dispatcher entry; keep deleteModule/deletedId source parity without inventing a mutation route.

Deleted records are hidden except for server-authorized `isAdmin && includeDeleted`, displayed as Deleted with their original raw money, then excluded from window totals by merged #329. Snapshots must be complete, trusted plain own-data objects (no getters/accessors), with source IDs unique per stream, canonical normalized business date/ts, finite amounts and no prototype-colliding IDs. Strictly require actor flags from trusted M04 server caller. Never automatically net Supplier Credit against Party roles or invent Cash Book entries, session openings, bank transactions, ledger corrections or refund postings.
