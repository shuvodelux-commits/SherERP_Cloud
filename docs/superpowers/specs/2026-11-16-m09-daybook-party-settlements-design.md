## Context and design choice
PR #369 (Sales/Purchase Return Day Book entries) was **still OPEN, unmerged** at the initial GitHub check, despite an owner message saying merged. This PR is an independent additive M09 slice created from main. It does not depend on PR #369 and must not silently merge it. Other merged pieces #361 Sales/Purchase rows, #350 actual Cash Book chronology, #342 Bank dedup and #329 window/totals are source-parity building blocks. Authorized, full D1 Day Book transaction snapshots are NOT implemented end to end.

**Chosen:** a pure, read-only projector `projectDayBookPartySettlements({customerLedgerRows,supplierLedgerRows},isAdmin=false,includeDeleted=false)`. Both arrays are **complete**, source-equivalent, already authorized and normalized. Filter Customer Ledger rows by exact Type = Payment or Advance Refund, Supplier Ledger rows by exact Type = Payment. Return original source order: all Customer Payments, then all Customer Advance Refunds, then all Supplier Payments, with every original Day Book output field. Do not add D1 readers or public RPC endpoints.

### Required parity
- Customer/Supplier Payment: `Payment Method || 'Cash'` and `settlementPaymentAmount_` cash-equivalent payment = roundMoney(Number(Payment Amount) || 0); **if Payment Amount blank/null/undefined, fallback to Credit** before rounding. Discount Amount = roundMoney(Number(Discount Amount) || 0); display ` — Discount N` on Notes/fallback only when discount > 0; no discount amount ever becomes Cash/Bank movement. Cash payments go to Customer `cashIn` / Supplier `cashOut`; Bank and Mobile Banking go to Customer `bankIn` / Supplier `bankOut`. Unsupported/noncash method -> zero money, never manufactured cash.
- Customer Advance Refund: `Number(Debit) || Number(Payment Amount) || 0` (do not infer refund from Credit); Cash -> `cashOut`, Bank and Mobile Banking -> `bankOut`; legacy blank method means Cash. Payment amount fallback applies only when Debit is zero or blank, matching source.
- Preserve `ts: Created At || Date` (old records date-only valid); business Date already canonical from source adapter. Preserve `Ledger ID`, source module, original Customer/Supplier ID for `openId`, `Customer Name`/`Supplier Name`, `Created By`, `Notes` fallback, due collection/payment/advance refund type, backdate fields and delete metadata. Exact original page maps: Customer Payment -> customers, Advance Refund -> customerLedger, Supplier Payment -> suppliers; original deleteModule lacks Advance Refund, do not fabricate authorization.
- Original `dayBookRow_` signed amount and field order; deleted records only visible to authenticated Administrator with includeDeleted, still carry original display amounts but are excluded from *later* totals by merged window module.
- Reject missing ledger groups, nonplain input/accessors, inherited fields, bad/sparse arrays, unsafe/duplicate source IDs, malformed canonical shop date/Created At, nonfinite actual money or discount. The original empty/missing amounts intentionally become zero, and Credit fallback for legacy payments is required. Do not use ambient time or infer source values. Do not net independent unified Party roles or treat a display-only amount as an actual D1 posting.

## Alternative not chosen
Adding a SQL union or coupling directly to M03 RPC would depend on unreviewed ledger tenancy/auth and all transaction-source completeness; a missing Source Ledger row or discount mistakenly counted as money would produce misleading totals. The pure projector, independently tested against unmodified frozen GAS blocks, stays bounded and independently mergeable.
