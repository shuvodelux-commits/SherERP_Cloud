## Risk and source-derived invariant

A successful `logout` marks `auth_sessions.revoked_at_ms`; restoration of that opaque bearer MUST remain denied. Once issued, a session's user ownership, token hash, authority-epoch snapshots and absolute creation/expiry timestamps must never change. Today the local D1 fixture constrains value shapes but permits `UPDATE auth_sessions SET revoked_at_ms=NULL` (resurrection), `user_id=?` (cross-user reuse, including Administrator with matched epochs), or `expires_at_ms=?` (extend token lifetime). This is a SQL-boundary integrity proposal, not permission to let untrusted callers perform SQL, and not a solution for a fully compromised DB administrator.
